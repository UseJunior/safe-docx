# Local save publication and recovery

`save` checks every requested destination's path policy before creating directories or writing output. Clean and tracked destinations must be distinct after resolving existing symlinks, dangling links and symlinked parents. Existing device/inode aliases are also rejected (`ALIASED_OUTPUT_PATHS`).

Absent targets have no inode to compare. For outputs sharing an existing ancestor, save mirrors their missing suffixes in a private probe directory on that ancestor's filesystem and reserves the names exclusively. This detects case/normalization aliases in filenames and missing parents using the filesystem's own rules, without globally lowercasing paths. Case-sensitive filesystems retain distinct names. Probes are removed before any requested parent directory, backup or output is created; probe cleanup failures retain exact recovery-path diagnostics. Path policy, existing-target shape and permission checks precede these private probe writes.

Existing symlinks retain write-through behavior: the link remains and its resolved target is written through its existing inode. Existing ownership/group, ACLs, extended attributes and POSIX permissions retain the filesystem's normal write-in-place semantics. Save never replaces an existing target with a staging inode or attempts to clone its security metadata. Multiply linked destinations conservatively fail with `HARDLINK_OUTPUT_UNSUPPORTED`, because writing one name also changes other linked consumers; this explicit refusal is separate from rejecting two outputs that alias each other. Non-regular targets and destinations without write access fail before staging. An existing file must also be readable for verified backup; if that is unsupported, save refuses before changing destination bytes.

Each output is staged in a private directory beside its resolved destination and its bytes verified. Existing originals are opened without truncation, checked for identity, and copied into backups whose complete bytes are verified before any destination changes. Publication writes the verified staged bytes through each existing handle, including an explicit final truncate for shorter files. It records publication start before a potentially partial write or truncate, so even a rejected write is restored through the same inode. New destinations use exclusive creation; an unexpected file created after preflight is neither overwritten nor removed. If staging, backup or publication fails, save restores existing contents and removes only newly created outputs it owns. Failed restoration retains the verified backup. It cleans partial stages and known empty staging directories without recursive deletion. New parent directories created for requested paths can remain empty after failure.

An ordinary recoverable error returns the usual save failure. If rollback needs attention, `SAVE_ERROR` includes `rollback_failures`: each entry names `path`, `operation`, `error` and, when present, `backup_path` and `staging_path`. The message also includes these exact paths. A backup that could not be restored is retained. Recover the listed originals before retrying; do not delete the backup to suppress the error.

Once both outputs are published, backup cleanup is separate from commit. A cleanup error returns success with `publication_cleanup_failures`, using the same path/operation fields, because both requested outputs already exist. Retained backups or empty staging directories can then be removed deliberately.

Staging and backups stay on each destination filesystem. Existing-inode writes and the pair are recoverable on ordinary failures, **not crash atomic**, including when destinations are on separate filesystems. A reader can observe bytes changing during publication. Probes observe inherited name-comparison behavior under the existing ancestor; identity checks and held handles do not eliminate TOCTOU races with external changes to directories, mounts, comparison settings or concurrent writers. This mechanism adds no new save parameters and preserves artifact/cache/generation policies.
