## ADDED Requirements

### Requirement: Versioned external conformance explorer contract

The repository SHALL generate a deterministic, schema-validated external
manifest that composes Safe DOCX registry sections, referenced schema
declarations, and capability-axis claims without replacing any authoritative
source artifact. The manifest SHALL carry an explicit contract version and
SHALL preserve targeted, Non-Goal, positive, gap, preservation-only, and
untested states without collapsing them into a boolean conformance claim.

#### Scenario: Downstream consumer reads one stable contract

- **GIVEN** the conformance registry, vendored schemas, and capability
  projection pass their existing checks
- **WHEN** the explorer exporter runs
- **THEN** it SHALL produce one JSON document that validates against the
  checked-in contract schema
- **AND** each exported record SHALL retain its source-owned stable identity
  and bounded status

#### Scenario: Unsupported state is exported honestly

- **GIVEN** a registry Non-Goal or a capability-axis row classified as
  `gap`, `non-goal`, or `untested`
- **WHEN** the manifest is generated
- **THEN** the output SHALL preserve that negative state
- **AND** SHALL NOT infer positive support from a citation, schema declaration,
  or source path

### Requirement: Stable cross-repository join identities

The explorer manifest SHALL expose section tuples, complete schema references,
and neutral capability-axis identities as stable joins. It SHALL expose neutral
scenario IDs only from existing validated mappings. QName, display title,
file/line-derived corpus identifiers, and repository paths alone SHALL NOT be
treated as globally unique join keys.

#### Scenario: Reused schema local name remains unambiguous

- **GIVEN** the same XML local name is declared in multiple schema contexts
- **WHEN** declaration records are exported
- **THEN** their identities SHALL retain schema reference, declaration kind,
  target namespace, and conformance-class context sufficient to distinguish
  them

#### Scenario: Renderer joins a capability claim to neutral data

- **GIVEN** a Safe DOCX projection row for a neutral capability and axis
- **WHEN** tests-renderer joins it to its independently pinned neutral registry
- **THEN** the join SHALL use `capabilityId + axis`
- **AND** the Safe DOCX manifest SHALL NOT duplicate the neutral capability
  definition or cross-implementation result

### Requirement: Deterministic generation and semantic drift checks

The explorer manifest SHALL be byte-identical for identical repository inputs,
SHALL NOT embed timestamps or Git HEAD, and SHALL be guarded by schema,
inventory, join, reference-resolution, and generated-output drift checks.

#### Scenario: Repeated generation is stable

- **GIVEN** no authoritative input changes
- **WHEN** the exporter runs twice on different dates or branches at the same
  content state
- **THEN** the generated bytes SHALL be identical

#### Scenario: Export omits or duplicates an authoritative record

- **GIVEN** a registry section, referenced schema declaration, or selected
  capability-axis row is missing from or duplicated in generated output
- **WHEN** the semantic check runs
- **THEN** the check SHALL fail before publication

#### Scenario: Generated artifact is stale

- **WHEN** an authoritative input changes without regenerating the explorer
  manifest
- **THEN** the drift check SHALL fail with a regeneration instruction

### Requirement: Downstream snapshot provenance belongs to the renderer

The Safe DOCX exporter SHALL omit self-referential build provenance such as
current commit and generation time. Consumer documentation SHALL require
tests-renderer to pin the exact Safe DOCX revision and content checksum beside
its committed snapshot, and production renderer builds SHALL not fetch mutable
remote data.

#### Scenario: Renderer refreshes its Safe DOCX snapshot

- **WHEN** tests-renderer imports a new explorer manifest
- **THEN** its refresh process SHALL record the exact Safe DOCX commit and
  manifest checksum
- **AND** a subsequent production build SHALL use that committed snapshot
  without a network fetch
