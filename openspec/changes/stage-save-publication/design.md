## Decisions
Resolve output policies before any directory creation. The helper checks all destinations before staging: resolved identity, device/inode identity, regular-file shape, write access and nearest existing parent access. Existing symlinks (including dangling links) write through to the policy-resolved target. Existing file permissions are copied to staging; new files retain normal umask behavior. Hardlinked destinations are rejected because replacing a directory entry cannot preserve write-through inode semantics. Parent directories are created as before, after preflight; newly created empty parents may remain after failure.

Use a private mkdtemp directory in each target's directory, a known staged file, and a known backup file. Back up all originals before publishing any output. Track prepared/staged/backed-up/published/restored/recovery-needed states locally. On ordinary failure restore backups directly over published files, remove newly published files, clean unused stages and remove only known empty private directories. Never delete a backup whose restoration failed. Report destination, backup/staging path and failed operation. After commit, cleanup errors are warnings, not a false assertion that the publication failed and rolled back.

The captured generation, artifact union, validation, selective policy and guarded cache publication from #1304 remain unchanged. Compute the revision summary before publishing so a subsequent metadata read cannot turn successful writes into a reported save failure.

## Limits
Each rename is local to the destination filesystem. The pair is recoverable after ordinary errors, not a distributed or crash-safe transaction. Permissions/ownership/ACLs beyond POSIX mode bits are not cloned; replacement creates a new inode. File and parent checks are preflight observations and cannot exclude external TOCTOU changes or concurrent writers. No recursive cleanup, fsync protocol or global transaction manager is introduced.
