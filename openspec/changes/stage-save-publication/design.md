## Decisions
Resolve output policies before any requested directory creation. The helper checks all destinations before staging: resolved identity, device/inode identity, regular-file shape, write access and nearest existing parent access. Existing symlinks (including dangling links) write through to the policy-resolved target. Existing inode/security metadata semantics are preserved by writing through that inode, without metadata cloning; new files retain normal umask behavior. Hardlinked destinations are conservatively rejected because changing one name also changes other linked consumers. Parent directories are created as before, after preflight; newly created empty parents may remain after failure.

Use a private mkdtemp directory in each target's directory, a known staged file, and a known backup file. Verify staged bytes. Open existing targets with r+ (no truncation), verify the opened identity, read originals, and verify each backup's complete bytes before publishing any output. Track prepared/staged/backed-up/publishing/published/restored/recovery-needed states locally. Register publication start before any potentially partial existing write or truncate. Use position-explicit short-write loops and final truncate through held handles; restore through those same existing inodes after ordinary failure. Never unlink or replace an existing inode to recover it. Exclusively open absent outputs and register owned creation before further IO; never overwrite or remove a new path whose exclusive open failed. Before removal/restoration check path identity and retain exact backup paths if identity changed. Clean only known stages/backups/empty private directories, retaining every verified backup whose restoration failed. After both publications, cleanup errors are success diagnostics, not a false assertion of rollback.

Missing outputs can alias on a case-insensitive filesystem even when neither exists. Group destinations by the device/inode of their nearest existing parent ancestor. If a group has a missing output, mirror each relative suffix under a private directory in that ancestor and reserve each filename exclusively. The actual filesystem detects name equivalence, including missing case-alias parents, while case-sensitive volumes permit distinct names. Remove only the explicitly created probe files/directories in reverse order; report exact paths if cleanup fails. All policy/type/permission checks precede probes, and probes precede requested directory creation and publication. This is an observation of inherited comparison rules, not protection against external directory/mount/configuration races.

The captured generation, artifact union, validation, selective policy and guarded cache publication from #1304 remain unchanged. Compute the revision summary before publishing so a subsequent metadata read cannot turn successful writes into a reported save failure.

## Limits
Staging and backups are local to the destination filesystem. The pair and in-place writes are recoverable after ordinary errors, not a distributed/crash-safe transaction or per-file rename atomicity guarantee. Existing inode ownership/ACL/xattr semantics are preserved by construction; file timestamps and kernel write side effects follow ordinary write-in-place behavior. Reading original bytes for verified backup may safely refuse targets the caller cannot read. File/parent/identity checks cannot exclude external TOCTOU changes or concurrent writers. Readers can observe an in-place publication. No recursive cleanup, fsync protocol, ACL framework or global transaction manager is introduced.
