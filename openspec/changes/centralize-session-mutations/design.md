## Decisions
Use a per-session FIFO promise queue and typed unpublished candidates, without a state-machine framework. Forks never call createSession, register with the manager, own new temp directories or clean active resources. Reads keep seeing the active document until publication. An object-identity check against the manager registry plus expiry validates the generation immediately before the synchronous commit.

DOCX forks copy private DOMs, relationships, ZIP entry metadata, bookmark reservations and mutation version, and retain the original on-disk XML baseline. Reloading a serialized package would reset minimal-reserialization history. Candidate revision allocator maps and attribution are copied too. Save-specific code and response/cache contracts remain owned by #1304 and are unchanged.

Compare complete deterministic DOCX package bytes (fixed entry dates), or ODF content XML, before publication. `DocxDocument.getMutationSnapshot()` captures internal state without registering it as an emitted artifact: malformed inputs being validated or refused are not exports. Actual `toBuffer()` exports retain schema-corpus capture unchanged. Selected revision IDs and attempted mutation counts alone do not prove change. No-op candidates are discarded, preserving the exact active document/cache/allocator objects. Changed candidates invalidate cached views and publish attribution at the committed revision. Selective policy remains sticky.

Google mutations use the same queue with confirmed remote-write versions instead of rollback snapshots. The provider advances confirmation only after batchUpdate succeeds and marks structure stale until refresh succeeds. The manager accounts for that success in a finally block, including failed refresh and retired sessions, without publishing into a replacement. Network requests are replaced with fake clients in tests. Broader stale-structure enforcement belongs to K (#1306).

## Trade-offs
Local no-op detection serializes twice, prioritizing correctness across direct-DOM and package mutators over speed. ZIP payloads are immutable and shared by forks; mutable entry tables and metadata are copied. Tool validation and ID/range resolution occur inside the queue against the candidate. Batch preflight stays advisory and each executed step revalidates through the boundary; successful earlier steps remain committed if a later step fails.
